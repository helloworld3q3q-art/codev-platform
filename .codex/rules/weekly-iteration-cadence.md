# 每周迭代节奏

> **规则性质**：工作流约定，非代码红线。决定 `docs/plans/roadmap-*/` 目录的生命周期。
> 历史 `docs/architecture/roadmap-*` 只作存量参考，不是新任务或续做任务的合法落点。

---

## 一、核心约定

- **每周一个协调迭代** = 一个 `docs/plans/roadmap-YYYY-MM-DD/` 目录
- 每周协调 plan 是任务索引和节奏说明，不复制独立任务的步骤、复选框或验收真值
- 未完成任务始终更新原任务 plan；新周协调 plan 只引用原 plan，不迁移、不冻结、不重复建档
- 新发现的独立变更任务仍须先建立自己的 plan，再登记到周协调 plan 和 roadmap `README.md`

**为什么大概率周末**:A 股周末不开盘,有完整时间盘点上周成果 + 排下周计划;周一开盘按新 plan 执行。但**不强制周六** —— 用户可能周五晚 / 周日 / 周一早盘前任意时段触发,AI 不要等到周六才主动建议,任何时候用户说"新一周 plan"都按 SOP 走。

---

## 二、目录命名规范

| 项 | 约定 |
|---|---|
| 目录名 | `roadmap-YYYY-MM-DD/`,日期取启动当天(用户实际触发日,大概率周六 / 周日) |
| 历史样例 | `roadmap-2026-05-11/` / `roadmap-2026-05-16/` / `roadmap-2026-05-23/` |
| 必含文件 | `next-plan-YYYY-MM-DD.md`（主 plan，首个写入）+ `README.md`（随后登记目录定位与速查） |
| 可选文件 | `feature-backlog-*.md` / `daily-summary-YYYY-MM-DD.md` / 子设计文档 |

---

## 三、规划日 SOP(6 步,不限定周六触发)

**触发时机**:用户说"新一周 plan" / "新建迭代" / "归档上周" 等任意暗示,AI 立刻按 SOP 执行。**不要主动催 / 不要等周六**。

### 1. 只读复盘上周（0.5h）

- 检查上周 `roadmap-YYYY-MM-DD/next-plan-*.md` 所有任务状态
- 确认完成项 ✅ / 未完结项 ⏳ / 锁定项 🔒
- 在内存中整理 1–2 条本周教训，等待步骤 2 首次写入协调 plan；本步骤不得修改任何文件或外部状态

### 2. 新建本周协调 plan（任务首个写入，15 分钟）

```
docs/plans/roadmap-{本周六YYYY-MM-DD}/
└── next-plan-{本周六YYYY-MM-DD}.md  # 协调 plan；必须首先写入
```

协调 plan 只写本周目标、节奏、约束和原任务 plan 链接。不得复制原任务的详细步骤、复选框或
验收标准；状态只标“截至规划时的快照”，实时状态以被引用的原任务 plan 为准。

### 3. 登记本周 README（15 分钟）

协调 plan 落盘后，创建或更新同目录 `README.md`，且必含：

- 顶部"当前主目录"标识
- 关联上周目录("../roadmap-{上周六}/")
- 关联累积期纪律真值源(若本迭代仍在累积期,通常 `../roadmap-2026-05-16/iteration-plan-2026-05-16.md`)

### 4. 更新上周目录的周节奏标记（15 分钟）

完成步骤 2、3 后，才允许修改上周 `roadmap-YYYY-MM-DD/README.md`，增加周协调归档标注和
本周协调 plan 链接。归档的只是上周协调周期，不冻结目录内仍未完成的独立任务 plan：

```markdown
> **周协调归档说明（YYYY-MM-DD 起）：** 上周协调周期结束；未完成任务继续更新各自原 plan。
>
> **本周协调目录 → [`../roadmap-{本周日期}/`](../roadmap-YYYY-MM-DD/)**
```

### 5. 引用上周未完结项（1h）

在本周协调 plan 中只增加链接，不复制任务正文：

- ⏳ 进行中任务 → 引用原任务 plan，状态继续写回原 plan
- 🔒 锁定项 → 引用原任务 plan，由原 plan 维护锁定条件
- 未启动候选项 → 只保留为候选；一旦成为变更任务，先单独创建任务 plan

**不重做、不双写**：已完成项可放周总结，不进入本周活动任务索引；未完成项不得在新周生成
第二套复选框。

本周协调 plan 使用以下模板：

按下列模板写 `next-plan-{本周六}.md`:

```markdown
# Next Plan — {本周六 YYYY-MM-DD} 周

> 起点:本周六
> 终点:下周六(或继承累积期终点 100 CLOSED)
> 上周协调:`../roadmap-{上周六}/next-plan-{上周六}.md`
> 状态口径:下表仅为规划时快照，实时状态以各原任务 plan 为准

## 一、本周核心目标(3-5 条)
## 二、原任务 plan 索引（链接 + 规划时状态快照）
## 三、本周排期(周一~周五逐日)
## 四、锁定项与候选项（只引用，不复制任务正文）
## 五、本周新增任务 plan 链接
## 六、禁止做清单(累积期纪律红线)
## 七、本周成功指标
## 八、持续运营 SOP(继承不变)
```

### 6. 索引与单一真值核对（15 分钟）

- 确认本周协调 plan 中每个活动项都链接到唯一原任务 plan
- 确认没有把原任务步骤、复选框或验收标准复制进本周协调 plan
- 必要时更新 `AGENTS.md` 顶部"当前迭代"标识；迁移期需要 Claude 兼容时再同步 `CLAUDE.md`

## 五、累积期(2026-05-12 ~ ≥100 CLOSED)特殊纪律

累积期内每周协调 plan 必须包含：

1. **CLOSED 样本累积进度表**(W1 ~ W7 周追踪)
2. **禁止做清单**(A19 扩库 / 改阈值 / ML 真训练 / 半 Kelly / 等)
3. **5 视角持续运营 SOP**(每日 / 每周 / 每月)
4. **累积期纪律真值源引用**(`../roadmap-2026-05-16/iteration-plan-2026-05-16.md`)

累积期结束后(≥100 CLOSED),进入下一战略阶段(Sprint-C 解锁 / M3-M6),纪律框架另起。

## 六、跨周延续保证

| 场景 | 处理 |
|---|---|
| 上周任务未完成且仍可做 | 更新原任务 plan；本周协调 plan 只保留链接和快照 |
| 上周锁定项条件仍未满足 | 在原任务 plan 维护锁定条件；本周只引用 |
| 上周候选项未启动 | 可保留候选引用；启动前先创建独立任务 plan |
| 上周事故未关 | 更新原事故/任务 plan；本周按 P0 引用 |
| 已完成项 | ✅ 进入周总结，不再进入活动任务索引 |

**禁止丢失或复制任务真值**：周转时必须人工 / AI 二次核查，确认每个 ⏳ / 🔒 项都引用唯一
原任务 plan，且状态仍由原 plan 维护。

---

## 七、归档目录的写入规则

周协调周期归档后，旧目录的协调 plan 和 README 只补客观事实、周总结或后续链接；但目录内
未完成的独立任务 plan **必须继续维护状态和验证证据**，直至任务完成或取消。

**禁止**：因跨周复制任务正文、复选框或验收标准；禁止为了“归档”冻结未完成任务 plan。
新发现的独立任务在当前日期 roadmap 中先建自己的 plan。

| 规则 | 关系 |

| `commit-pr-conventions.md` | commit 不带 AI 痕迹,本规则不重复 |

本规则只管周协调节奏与目录索引，不改变 `workflow.md` 的每任务单一计划真值规则。
