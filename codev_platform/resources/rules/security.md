# 敏感信息与安全

本规则约束跨项目通用安全边界。项目领域合规、行业免责声明、生产部署细节由项目本地规则维护。

---

## 1. 敏感信息

| 项 | 处理方式 |
|---|---|
| API key / token / cookie | 只放环境变量、用户配置或密钥管理;禁止写入仓库 |
| 数据库 / 队列 / 对象存储连接串 | 用环境变量或私有配置;日志中脱敏 |
| 用户身份 / 租户身份 | 来自认证上下文,禁止由 client 自传覆盖 |
| MCP 服务 URL / token | 配置可提交,凭证不可提交 |
| `.env` / 私有证书 / 私钥 | 必须 gitignore;误提交立即停手处理泄露风险 |
| 用户数据 / 生产数据 | 不入仓库;测试用夹具或脱敏样本 |

---

## 2. 日志与错误

- 不打印完整 token、Authorization header、cookie、密码、私钥。
- 错误响应可以带 trace id,不要带内部堆栈、密钥路径或完整环境变量。
- AI / MCP 工具返回给模型的内容要避免夹带 secret。
- 诊断输出需要路径时优先使用 repo 相对路径。

---

## 3. MCP / agent 安全边界

- 个人记忆必须按用户身份隔离;共享开发机不能把本地身份当团队身份。
- 跨项目数据访问必须带 project_id / tenant / scope,不能靠当前目录绕过授权。
- SSE / HTTP 工具服务开放到非本机环境前必须补认证、TLS 或反向代理保护。
- shell、文件写入、网络调用等高权限工具必须有明确边界和审计日志。

---

## 4. Web / API 通用边界

- 对外 API 不返回 secret 或内部异常堆栈。
- 前端不把长期 token 写进 localStorage,除非项目安全规则明确允许。
- OpenAPI / 调试端点暴露到非本机环境前必须加鉴权。
- 上传/导入功能要限制文件类型、大小和路径穿越。

---

## 5. 已有 assertion 兜底

🟡 部分 assertion 化:

- 许多项目已有鉴权/越权单测,但覆盖范围由项目决定。
- `.gitignore` 可覆盖常见本地环境文件,但不能替代 secret scanning。

盲区:

- 缺通用 secret scanning CI 模板。
- 缺 SSE / 调试端点暴露面自动检测。
- 缺日志脱敏快照测试模板。
