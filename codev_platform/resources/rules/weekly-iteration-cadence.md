# 每周迭代节奏

> **规则性质**:工作流约定,非代码红线。决定 `docs/architecture/roadmap-*/` 目录的生命周期。

---

## 一、核心约定

- **每周一个大迭代** = 一个 `docs/architecture/roadmap-YYYY-MM-DD/` 目录
- **每周新建 plan**(具体日期不固定,大概率是周六 / 周日;以用户实际触发为准)+ 上一周自动归档
- **新 plan 继承上周未完结项**,不丢失,不重做

**为什么大概率周末**:多数团队周末或周初更适合盘点上周成果 + 排下周计划。但**不强制周六** —— 用户可能任意时段触发,AI 不要等到周六才主动建议,任何时候用户说"新一周 plan"都按 SOP 走。

---

## 二、目录命名规范

| 项 | 约定 |
|---|---|
| 目录名 | `roadmap-YYYY-MM-DD/`,日期取启动当天(用户实际触发日,大概率周六 / 周日) |
| 历史样例 | `roadmap-2026-05-11/` / `roadmap-2026-05-16/` / `roadmap-2026-05-23/` |
| 必含文件 | `README.md`(目录定位 + 速查) + `next-plan-YYYY-MM-DD.md`(主 plan) |
| 可选文件 | `feature-backlog-*.md` / `daily-summary-YYYY-MM-DD.md` / 子设计文档 |

---

## 三、规划日 SOP(6 步,不限定周六触发)

**触发时机**:用户说"新一周 plan" / "新建迭代" / "归档上周" 等任意暗示,AI 立刻按 SOP 执行。**不要主动催 / 不要等周六**。

### 1. 复盘上周(0.5h)

- 检查上周 `roadmap-YYYY-MM-DD/next-plan-*.md` 所有任务状态
- 确认完成项 ✅ / 未完结项 ⏳ / 锁定项 🔒
- 记 1-2 条本周教训(如有事故)

### 2. 上周目录归档(15 分钟)

修改上周 `roadmap-YYYY-MM-DD/README.md` **顶部**加归档标注:

```markdown
# YYYY-MM-DD 迭代规划目录(🗄️ 已归档 / 本周交付归档真值源)

> **🗄️ 归档说明(YYYY-MM-DD 起)**:本目录已转为**本周交付归档 + 累积期纪律真值源**(如有),保持不动。
>
> **当前主目录 → [`../roadmap-{下周六日期}/`](../roadmap-YYYY-MM-DD/)**
```

### 3. 新建本周目录 + README(15 分钟)

```
docs/architecture/roadmap-{本周六YYYY-MM-DD}/
├── README.md              # 主目录定位 + 上周继承项速查 + 本周新增任务
└── next-plan-{本周六YYYY-MM-DD}.md  # 主 plan
```

README 必含:
- 顶部"当前主目录"标识
- 关联上周目录("../roadmap-{上周六}/")
- 关联累积期纪律真值源(若本迭代仍在累积期,通常 `../roadmap-2026-05-16/iteration-plan-2026-05-16.md`)

### 4. 继承上周未完结项(1h)

从上周 next-plan 复制以下项进新 plan:
- ⏳ 进行中任务 → 转入新 plan 主线
- 🔒 锁定项 → 转入新 plan 锁定列表(注明原锁定条件)
- 待用户拍板的 backlog 项 → 转入新 plan §六 候选清单

**不重做**:已 ✅ 项明确标"上周完成,本周不重复"。

### 5. 新 plan 主体(1-2h)

按下列模板写 `next-plan-{本周六}.md`:

```markdown
# Next Plan — {本周六 YYYY-MM-DD} 周

> 起点:本周六
> 终点:下周六(或继承累积期终点 100 CLOSED)
> 继承:`../roadmap-{上周六}/next-plan-{上周六}.md`

## 一、本周核心目标(3-5 条)
## 二、当日交付(周六规划完结时,周六已做的)
## 三、本周排期(周一~周五逐日)
## 四、上周继承的未完结项(分: 主线 / 锁定 / backlog)
## 五、新增任务(本周新发现 / 用户拍板)
## 六、禁止做清单(累积期纪律红线)
## 七、本周成功指标
## 八、持续运营 SOP(继承不变)
```

### 6. 索引更新(15 分钟)

- 上周 `roadmap-YYYY-MM-DD/README.md` 文档清单加链接指向本周新 plan
- 必要时更新 `CLAUDE.md` 顶部"当前迭代"标识

---

## 四、每周可选交付

| 项 | 频次 | 输出 |
|---|---|---|
| 周一 ~ 周五 daily-summary | 每日 | `roadmap-YYYY-MM-DD/daily-summary-YYYY-MM-DD.md` |
| 周中事故复盘 | 触发时 | `docs/operations/incident-YYYY-MM-DD-*.md`(不入 roadmap) |
| feature backlog 新增 | 触发时 | 同目录 `feature-backlog-*.md` |
| 子设计文档 | 触发时 | 同目录 `*-design.md` |

---

## 五、项目特殊纪律

若项目处在某个阶段性纪律内,每周新 plan 必须包含:

1. 阶段目标和度量口径。
2. 禁止做清单 / 锁定项。
3. 每日 / 每周 / 每月运营 SOP。
4. 阶段纪律真值源引用。

阶段结束后,在新 plan 中明确关闭条件和下一阶段入口。

---

## 六、跨周延续保证

| 场景 | 处理 |
|---|---|
| 上周任务未完成且仍可做 | ⏳ 继承到本周主线 |
| 上周锁定项条件仍未满足 | 🔒 继承到本周锁定列表 |
| 上周 backlog 未启动 | 继承到本周 backlog,无截止日 |
| 上周事故未关 | 转入本周主线 P0,直至关闭 |
| 已完成项 | ✅ 不再出现在本周 plan |

**禁止丢失任务**:周转时必须人工 / AI 二次核查,确认上周文档每个 ⏳ / 🔒 / backlog 项都在本周有归宿。

---

## 七、归档目录的写入规则

🚨 **已归档目录(README 顶部有🗄️标识)中的所有文件原则上不再修改**,例外:
- 修正笔误 / typo
- 加链接指向新目录
- 补遗漏的客观事实(如某 commit 实际日期错)

**禁止**:在归档目录新增任务 / 修改任务状态。新发现一律进当前主目录。

---

## 八、与 .claude/rules 其他规则的关系

| 规则 | 关系 |
|---|---|
| `commit-pr-conventions.md` | commit 不带 AI 痕迹,本规则不重复 |
| `verification-checklist.md` | 改动后验证,本规则不重复 |
| 项目本地规则 | 项目架构/业务纪律由本地规则维护,本规则不重复 |

本规则只管"目录生命周期",不涉及代码红线。

---

## 九、视角支撑

| 视角 | 本规则的价值 |
|---|---|
| 项目管理 | 周追踪目标、完成项、未完结项 |
| 工程 | 上下周文档结构一致,新协作者上手快 |
| 合规 / 审计 | 每周决策留痕 + 锁定条件可追溯 |
| 架构 | 阶段性约束和技术债继承不丢 |
