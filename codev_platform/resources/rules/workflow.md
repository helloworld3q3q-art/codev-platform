# 跨项目协作工作流基线

本文档是 codev-platform 分发给各项目的**通用工作流基线**。它不假设项目使用哪种语言、框架、数据库、前端或部署方式。

项目自己的架构事实必须放在本仓 `.claude/rules/` 中,例如:

- `project-profile.md`:技术栈、目录、服务、数据源、生成物、禁改项。
- `architecture-map.md`:前端/后端/数据/任务/基础设施的链路映射。
- 领域规则:业务枚举、表结构、合规文案、计费、风控等。

通用规则只回答"怎么协作、怎么查、怎么验证";项目本地规则回答"本项目具体是什么"。

---

## 1. 默认不读取

除非排查目标直接指向:

- 依赖目录:`node_modules/`、`.venv/`、`venv/`、`vendor/`
- 缓存和构建物:`dist/`、`build/`、`target/`、`.next/`、`.nuxt/`、`.umi/`、`__pycache__/`、`.pytest_cache/`
- AI / 搜索索引:`.codegraph/`、`data/chroma/`、`data/codegraph_ext/`
- 大型 dump / 二进制:`*.sql`、`*.gz`、`*.zip`、`*.sqlite*`、`*.png`
- 锁文件:默认不读;排查依赖解析时再定向读
- 生成文件:默认不全文读;需要接口签名或类型时定向读

项目若有额外生成物或禁读目录,必须在本地 `project-profile.md` 补充。

---

## 2. 可读但默认禁改

| 范围 | 通用处理 |
|---|---|
| 生成文件 | 优先走生成命令;确需手改要说明原因 |
| 已发布迁移 / 历史数据脚本 | 默认不回改;走 forward 变更或项目规定流程 |
| 依赖锁文件 | 只有依赖变更任务才改 |
| 运行态数据 / 索引 / 缓存 | 不手改;走重建/清理命令 |
| 认证、权限、生产配置 | 改前列影响面和回退方式 |
| `.mcp.json` / AI 工具配置 | 改前说明会影响哪些 MCP |

---

## 3. 任务分级

| 等级 | 适用范围 | 必做动作 |
|---|---|---|
| L1 小改 | 文案、注释、单文件小 bug、局部样式,不改对外契约 | `git status -s` + 定向读文件 + 最小验证 |
| L2 单层 | 同一技术层或模块内多文件联动,可能影响调用方 | 查项目本地规则 + codegraph 定义/调用方/影响面 + 定向验证 |
| L3 跨层 | API/事件/消息/数据模型/存储/schema/生成链路/权限/路由等跨层契约 | platform-docs + codegraph + graph(如已接入) + 验证闭环 |
| L4 高风险 | 依赖、迁移、生产配置、长驻服务、认证/RBAC、索引重建、发布/打包 | 先列影响面、回退方式、禁改项和串行资源 |

L1 命中 §2 默认禁改范围时,升级到 L3/L4。

---

## 4. MCP-first 口径

MCP 优先于 Grep + Read。Grep 只在以下场景兜底:

- 未提交改动命中查询范围
- 索引滞后
- MCP 不可用
- 核对最新源码行号

`codev-platform sync-hooks` 会分发 PreToolUse(Grep) 提醒 hook,但 hook 只提醒,不替代任务判断。

| 问题 | 首选 |
|---|---|
| 找符号、定义、调用方、影响面 | `codegraph_*` |
| 找规则、设计、事故、历史决策 | `platform-docs search_docs` |
| 找跨层链路、数据流、页面/接口/表/任务关系 | `graph` 工具(项目已接入时) |
| dirty 命中索引范围 | MCP 只作导航,关键结论回读真实文件 |
| MCP 不可用 | 说明一次原因,再用本地搜索 + Read 兜底 |

---

## 5. 改前影响面

L2/L3/L4 修改前先压缩影响面:

```markdown
合并影响面:
- 等级:
- 文件范围:
- 项目本地规则:
- CodeGraph 结论:
- graph 结论(如适用):
- dirty-index / 真实文件:
- 禁改项 / 生成项:
- 验证:
```

L1 不强制成文;范围扩大后补齐。

首次修改前说一句:

`本次触及 <层>;适用规则 <文件名>;关键约束 <一句话>;验证方式 <命令>`

---

## 6. 通用任务映射

| 改动类型 | 必读 / 先查 | 最小验证 |
|---|---|---|
| 查规则 / 项目结构 | `project-profile.md` + 本文件 | 无代码改动则说明结论来源 |
| 找函数 / 类 / 组件 / 命令入口 | codegraph 定位 | 回读目标文件 |
| 找调用方 / 影响面 | codegraph callers/impact | 列直接调用方和需同步文件 |
| 前端页面 / 组件 | 项目前端规则 + 调用点 | 项目前端 lint/typecheck/单测 |
| 后端接口 / route / handler | 项目后端规则 + API 契约 | 后端定向测试;契约改动补消费者检查 |
| 数据模型 / schema / 存储字段 | 项目数据规则 + graph 链路(如有) | migration/schema 测试 + 读写路径测试 |
| 消息 / 事件 / 定时任务 | 项目任务/消息规则 + 生产者消费者链路 | 生产/消费两侧定向测试 |
| 生成链路 | 项目生成规则 | 生成命令或 dry-run + 生成物差异检查 |
| 认证 / 权限 / 安全 | `security.md` + 项目安全规则 | 授权/越权测试 |
| AI 工具 / MCP / 索引 | `ai-tools-mcp.md` | status/dry-run/目标测试 |
| 文档 / 规则 | 本文件 + 目标规则 | 引用路径存在 + 关键字/断链扫描 |
| Hook / 本地工具 | 对应工具规则 | dry-run + 目标单测 |

项目有更具体规则时,项目本地规则优先。

---

## 7. 跨层改动定义

任一情况视为跨层:

- 对外 API、RPC、事件、消息、文件格式、schema 变化
- 存储字段 / 索引 / 迁移影响读写路径
- 前端请求参数、展示字段或生成类型变化
- 权限、认证、租户、用户身份边界变化
- 任务调度、异步消费、缓存失效、索引重建变化
- 公共库 / SDK / CLI / 配置影响多个项目或模块

跨层改动必须说明消费者和验证闭环。没有 graph 时,用项目本地规则 + codegraph + 真实文件读取兜底。

---

## 8. 改动原则

- 单一职责:只改本次范围,不顺手清理无关问题。
- 项目事实本地化:不要把某个项目的架构、业务字段、表名、合规口径写进分发规则。
- 匹配现有风格:优先本项目已有 helper / test / 命名。
- 不写未来代码:不加未接线 flag、TODO 占位或空抽象。
- 不动用户改动:发现未知 dirty 文件先读最新内容;无关则忽略。
- 写侧串行:索引重建、代码生成、迁移、长驻服务重启不能并发。

---

## 9. 错误处理

- 不绕过:`--no-verify`、`eslint-disable`、`# type: ignore`、跳测试都要有正当理由。
- 不盲目重试:命令失败先读输出。
- 不修改依赖锁/环境来掩盖本次问题。
- 定向验证优先;全量失败时区分本次相关和既有失败。
- Windows 命令按 `windows-powershell.md` 处理编码和路径。

---

## 10. 验证矩阵

| 改动类型 | 最小验证 |
|---|---|
| 单文件逻辑 | 对应单测 / lint / typecheck |
| 前端 | 项目前端 lint/typecheck/组件测试 |
| 后端 | 目标 handler/service/repository 单测或接口测试 |
| 数据 / schema | migration/schema 检查 + 读写路径测试 |
| 跨层契约 | 生产者 + 消费者两侧验证 |
| AI 工具 / MCP | status/dry-run + 目标测试 |
| 文档 / 规则 | 引用路径存在 + 断链扫描 |
| Hook / 脚本 | dry-run + 幂等测试 |

无法验证时必须说明原因。

---

## 11. 禁止 AI 自动执行的命令

默认不自动执行:

- 依赖安装
- 长驻服务启动
- 重型构建 / 发布
- 全量索引重建 / 大范围数据迁移
- 破坏性 git 操作

一次性检查、定向测试、dry-run 可按需运行。

---

## 12. Subagent 模板

派 subagent 只给边界,不要塞整份规则:

```markdown
【目标】30 字以内
【文件路径】1-3 行绝对路径
【禁止】≤5 条
【必查】search_docs / codegraph / graph 的具体查询
【验证】1-2 条命令
【输出长度】如 150 行内
```

Subagent final 必须列 MCP 调用清单、本地搜索兜底理由和验证结果。

---

## 13. 已有 assertion 兜底

🟡 部分 assertion 化:

- `sync-hooks` settings merge 幂等单测。
- resources package-data importlib 定位单测。
- CLI 子命令注册测试。
- Grep 前 MCP-first hook 提醒。

盲区:

- 项目是否补齐 `project-profile.md` 仍靠接入检查。
- MCP-first 只对 Grep 有 hook,对 Read/终端搜索没有硬拦。
- 跨层链路质量依赖各项目 graph/codegraph 索引覆盖度。
