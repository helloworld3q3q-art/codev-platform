AI 辅助开发架构

这是一张面向开发协作的架构图:从源码、规则、Skills、文档,到三套 MCP、三类本地索引、GPU 模型、daemon/proxy、多会话并发、验证和 token 节省路径。新增 Agent 服务 + Memory 基建这一主动协作轴:常驻 HTTP Agent(多模型可插拔 + 6 只读工具)叠加四作用域分层记忆(召回融合 + 生命周期),与上面的被动检索管道互补。

一图总览

主流程按 `ai-toolchain-guide.html` 对齐:源码、规则、文档和迁移先作为数据源进入触发器与索引器,再写入本地存储,由 MCP 服务进程按需读取,最后被多个 AI 会话消费。共享 daemon、dirty gate、写侧锁和验证闭环保留为治理节点。

Agent 服务 + Memory 基建(主动协作轴)

上面的管道是"AI 调 MCP 被动检索";这一节是新增的"常驻 Agent 主动协作 + 分层记忆"轴。Agent 是 HTTP 服务(FastAPI),多模型按协议族可插拔(Anthropic 协议 + OpenAI 兼容协议族一个适配器全吃),自带 6 只读工具(复用上面的 codegraph / graph / search_docs)与防空转硬护栏;Memory 基建提供组织 / 团队 / 项目 / 个人四作用域记忆,落 PG 独立库,召回时跨作用域合并 + 冲突消解(红线最高),会话与记忆跨重启持久化,生命周期含 supersede / TTL 归档 / LLM 压缩融合。身份是请求级三元组 (org_id, user_id, project_id),多租户物理隔离。

分层职责

1. 数据源层

Python、Java、前端、SQL、Rules、Skills、Docs 都是索引输入。业务代码和规则文档不是上下游关系,它们共同作为 AI 可检索的数据源。

2. 触发与门禁层

主路径是 commit hook 自动按命中文件刷新索引;`update-local-ai` 只作为兜底 / 全量刷新入口。dirty-index 和 L1-L4 workflow 决定是否信任 MCP、是否升级到跨层验证。

3. 索引器与模型层

Chroma indexer 三级 chunk 切分(heading → paragraph → hard split,target 1000 / max 1500 字符),调用 Qwen3-Embedding-0.6B 向量化 + Qwen3-Reranker-0.6B 精排;同时 词法 倒排索引在 daemon 启动 / chroma 重建时同步构建(中英混合 tokenizer:jieba + ASCII 正则识别代码符号 / 版本号 / 规则编号)。CodeGraph sync 解析代码符号和调用;graph(统一图谱)build 抽取 API-SQL-文件链路 + 业务域。独立 Flyway SQL 经过 commit/dirty 门禁后进入 graph;承载 SQL 的 Java/Python 代码文件会作为代码进入 CodeGraph,其中 SQL 变量/方法名可被搜到,但表/字段语义仍以 graph 为准。

4. 本地存储层

Chroma、codegraph.db、graph store 和 memory 保存可查询上下文。它们是读多写少资源,重建必须串行,读取允许多会话并发。

5. MCP 服务层

platform-docs、codegraph、graph 把本地存储包装成 AI 可调用工具。platform-docs / graph 走平台 SSE 服务,codegraph 经 mcp-proxy 包成 SSE。

6. 消费与闭环层

AI 会话根据任务等级选择 MCP 和本地文件兜底。核心输出应是“合并影响面 + 修改边界 + 验证清单”,前端页面只负责把同一份结果可视化。

开发配置入口

这层决定 MCP 实例为什么会出现多份。当前项目不是单一路径启动:Claude Code 和 Codex 入口不同,但都指向同一组三个 MCP。

入口 真实配置 作用 需要注意
Claude Code 项目根 `.mcp.json` 声明 `codegraph`、`platform-docs`、`graph` 三个 MCP(SSE)。 不能随便改,否则 Claude Code 项目 MCP 会受影响。
Codex `scripts/codex-platform.cmd` → `codex-platform.ps1` → `-c mcp_servers...` 强制把同一组三个 MCP 注入 Codex,并设置项目根目录。 如果 Codex 同时读取项目 `.mcp.json`,会启动两套 stdio MCP。
Claude hook `.claude/settings.json` SessionStart 会话开始时跑 `dirty-index-check.ps1 -Json`,提醒索引是否可能滞后。 这是 Claude Code 配置;Codex 侧仍要靠 workflow 自检。
Git hook `.git/hooks/post-commit` → `tools/dev/post-commit.ps1` 提交后按命中文件自动触发 Chroma / codegraph 的后台刷新。 文档变更主要刷新 Chroma;代码图谱只在命中对应路径时刷新。
兜底刷新 `tools/dev/update-local-ai.ps1` hook 漏触发、索引疑似过期、周末全量维护时手动运行。 不是日常主路径;多会话时应避免并发运行。
platform-docs `tools/chroma/platform-docs-mcp.cmd` → `platform_docs_launcher.py` 每个会话先启动轻量 stdio proxy,再共享一个 HTTP/SSE daemon 和 GPU 模型。 多 proxy 正常;多 daemon 才是问题。
codegraph `codegraph serve --mcp` 每个会话一个 stdio server,读取 `.codegraph/codegraph.db`。 读侧可多份;重建时会被 lock / MCP 持有检测保护。
graph(统一图谱) 平台 SSE 服务(:18092) 读取 `data/codegraph_ext//` 统一图谱存储,提供链路 / 业务域查询。 读侧可多份;构建走临时库和 SQLite backup 发布。
当前核对结论:如果只打开一个 Codex 窗口仍看到两组 `codegraph / platform-docs proxy / graph`,优先怀疑是 `.mcp.json` 与 `codex-platform.ps1` 的 `-c mcp_servers...` 双路径同时生效,不是业务数据库数据错乱。

MCP 与索引

组件 当前形态 主要用途 防错机制
platform-docs stdio proxy → shared HTTP daemon;Hybrid 检索:Qwen3-Embedding 向量 + 词法 倒排,RRF 融合后 Qwen3-Reranker 精排 查 Rules、Skills、Docs、Memory、决策日志(dev_log)、工具栈事故(tooling_incident)和历史决策。中英混合分词(jieba + ASCII 正则)对代码符号 / 版本号 / 规则编号召回精确,词法 命中向量漏掉的精确 token,reranker 给最终相关性。 spawn lock、health endpoint、listener PID + GPU PID 检查、Chroma reindex lock、DOC_PATTERNS 子目录覆盖 audit(pre-push gate 6/6)、jieba / rank_词法 缺失自动降级纯向量。
codegraph 每会话 stdio server 查符号、定义、调用方、被调用方和影响范围。 rebuild lock、DB integrity 检查、WAL 检查、多会话只提示 INFO。
graph(统一图谱) 平台 SSE 服务(:18092) 查跨层链路 + 业务域,确认接口、SQL、文件引用关系。 临时库构建、SQLite backup 发布、freshness 检查、多会话链路观测。
dirty-index 本地检查脚本 判断未提交改动是否命中索引范围。 命中时 MCP 只能作参考,关键判断读真实文件。

并发治理

多会话是正常工作方式。当前策略不是禁止多进程,而是按资源类型区分:读可以并发,写必须串行,重资源必须单例。

资源 允许并发 当前保护
AI 会话 / proxy 允许多个。 每个会话声明文件范围;不得同时改同一文件;修改前后看 `git status`。
MCP 查询 允许多个读请求。 dirty-index 决定索引可信度;命中 dirty 后读真实文件兜底。
GPU 模型 不允许多份重模型 worker。 platform-docs shared daemon + spawn lock + health 检查。
索引重建 不允许并发写。 Chroma reindex lock、CodeGraph rebuild lock、graph 临时库发布。
源码文件 不同文件可并行。 发现他人改动先读最新内容,不回滚未知改动。

开发工作流

这部分对应 `.claude/rules/workflow.md` §3.0c 和 `AGENTS.md` 的改前门禁:AI 做 L2/L3/L4 时,先产出合并影响面,再决定文件范围、生成边界和验证命令。

0. 自报 trigger

会话内首次 Bash(非 ls/git status 等只读)/ Edit / Write 之前必须输出 [L1|L2|L3] 任务: ... → MCP 计划: ...。CLAUDE.md §0.13 硬门禁,把"知道映射表存在"转成"动手前真查"。

1. 判级

L1 小改轻流程。L2 单层任务查规则和代码影响面。L3 跨层查三套 MCP。L4 高风险先确认边界。

2. 查证

先产出合并影响面:规则靠 platform-docs,代码结构靠 codegraph,数据契约和 SQL 链路靠 graph。dirty 命中时读真实文件。

3. 定边界

把合并影响面压成文件归属、禁改项、生成项、验证命令。这里是提效核心,不是前端展示。

4. 修改

只改本次范围。生成物、历史迁移、索引产物和缓存默认不手改。

5. 验证

优先定向验证。前端、Java、Python、SQL、AI 工具链分别跑对应最小检查。

合并影响面 来源 开发流程里的用途
规则 / 红线 / skill 步骤 platform-docs 决定能不能改、必须怎么改、哪些命令禁止自动跑。
函数 / 类 / 调用方 / 影响面 CodeGraph 决定改哪些代码文件、哪些调用方需要同步、哪里需要补测试。
SQL / 表 / 字段 / endpoint / Python writer-reader graph(统一图谱) 决定跨层契约、DB 写入、Mapper、前端 API 类型和数据一致性风险。
真实工作树 dirty-index + 本地文件 发现索引滞后时兜底,防止多个会话同时改同一文件。
等级 典型范围 工具强度
L1 文案、注释、局部样式、单文件小修。 git status + 定向读文件 + 最小验证。
L2 单模块或同层多模块联动,不改 API / DB / DTO / enum / 跨语言字段契约。 模块 rules + codegraph 调用方和影响面;追问数据来源/去向时加 graph。
L3 DTO、API、SQL、写库字段、migration、enum、跨层契约。 platform-docs + codegraph + graph + 验证闭环。
L4 生成文件、依赖、全局 runtime、AI 工具链、历史数据边界。 先说明影响范围;禁改项拒绝或走正确生成流程。

效率与准确率

目标 来源 表现
准确率 Rules/Skills 语义检索 + 词法 精确符号召回 + RRF 融合 + reranker + codegraph 影响面 + graph 跨层链路。 减少凭记忆改代码,先查约束和影响面再编辑。词法 hybrid 补救向量漏掉的精确 token(版本号 / 规则编号 / 罕见术语)。
效率 GPU 模型常驻 daemon + 多会话共享 + 定向 MCP 查询。 减少冷启动、重复模型占用和全仓搜索。
Token 文档、规则、Skills 留在索引库,按 query 返回 top-k chunk。 避免每次把大量 Markdown 全塞进上下文。词法 路径 0 API token(纯本地)。
可观测性 ai-health、dirty-index、reindex log、search recall log(JSONL 记 词法_used / rerank_score)。 发现 daemon、索引、新鲜度、dirty、词法 命中率和使用率问题。
使用率判读 search_recall 看检索质量;mcp usage 7d 看 platform-docs 痕迹;mcp adoption 看 L2/L3 候选提交。 低 commit 比率不直接等于低价值;L2/L3 候选多但 search_docs 少,才说明执行纪律不足。

边界与验证
