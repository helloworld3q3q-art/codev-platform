这平台是什么 (一句话 × 4)

1. 真值源仓

Chroma 常驻服务、词法召回、统一图谱、project_id / paths / config 这些核心代码集中在这。业务仓 tools/_platform/ · tools/chroma/ 全是 thin shim re-export 自本仓。

2. pip 包

pip install -e D:\WorkSpace\codev-platform → 业务仓的 chroma .venv / system python 都能 import codev_platform.*。-e 软链,改源码即生效。

3. CLI 入口

codev-platform 6 子命令:init · current · list-projects · validate · sync-rules · sync-skills · config。新业务仓接入靠它。

4. 用户配置中心

~/.codev-platform/config.json 单一文件:模型路径 / daemon 端口 / 数据基目录 / search 参数。换机器只改这,代码不动。

平台的作用与优势

一句话定位:把"多项目 AI 协作"里重复的基建 —— 检索 / 规则 / 模型 / 记忆 / 运维 —— 收敛成一份自包含、多租户、可插拔的平台,让 AI 既能查(代码/契约/规则)、又能记(分层记忆)、还能主动干(常驻 Agent),且按需演进不背早期负债。

作用 —— 平台在做的 5 件事

1. 一份真值源,多项目复用

核心代码 / 规则 / 技能 / 配置集中本仓,业务仓只靠 shim + sync 消费,不各自拷贝、各自演化。改一处,全仓生效。

2. AI 协作的检索底座

三套 MCP(代码图谱 / 跨层链路 / 文档检索)预索引。AI 改代码前先查定义、调用链、影响面、规则,少凭记忆瞎改 —— 准确率的地基。

3. 常驻 Agent 服务

FastAPI 多模型可插拔(按协议族,加厂商≈零代码),自带 6 只读工具 + 防空转护栏。从"被动检索"升级为"主动问答 / 执行",可被 widget / CLI / 会话调用。

4. 分层记忆基建

组织 / 团队 / 项目 / 个人四作用域,跨会话不失忆;召回融合 + 冲突消解(红线最高)+ 生命周期(TTL / 压缩)。让 AI 记住偏好与约定,不必每次重教。

5. 多租户 + 跨平台运维

一套服务多项目按 project_id / org/user 物理隔离;运维编排升级为跨平台 CLI,Win / Mac / Linux 一份 config 通用。

本轮把工具栈从"Windows 专属 + 业务仓寄居"重构为"跨平台 + 本仓自有运行时",抹掉了所有机器路径硬编码,补齐了测试与 CI。

分发链路

真值源 → 业务仓的 3 条独立通道,各自演化:

通道机制改动后业务仓如何拿到
核心代码 pip install -e 软链 改本仓 → 业务仓即时生效 (不需重装)。但 daemon 进程持旧代码,需 Stop-Process -Id (Get-NetTCPConnection -LocalPort 18083).OwningProcess -Force 重启。
shim re-export 业务仓内文件硬编码 from codev_platform.xxx import * 新增 symbol 必须手动在业务仓 shim 加一行 re-export,否则业务仓引用不到。
规则 / Skill sync-rules / sync-skills 本仓改真值源 → 各业务仓手动跑 sync 命令拉副本。不自动推。
⚠️ 改 codev-platform 后必走 4 步:① 本仓 commit + push ② 本仓 .venv 已 editable,改源码即生效(仅新增重依赖才重装) ③ 加了 symbol 时业务仓 shim 加 re-export ④ daemon 持旧代码时重启让进程加载新代码。

并发治理

多项目 + 多会话是常态。策略不是禁止多进程,而是按资源类型区分:读可以并发,写必须串行,重资源必须单例。这套语义靠 codev_platform/chroma/server.py 的 contextvar 路由 + GPU semaphore + reindex lock 落地。

资源 允许并发 当前保护
AI 会话 / proxy 允许多个(跨项目 + 同项目多会话)。 每个会话声明文件范围;不得同时改同一文件;修改前后看 git status。
MCP 查询 允许多个读请求(跨项目按 contextvar 隔离)。 dirty-index 决定索引可信度;命中 dirty 后读真实文件兜底。
GPU 模型 不允许多份重模型 worker。 platform-docs shared daemon + spawn lock + health 检查;所有项目共享同一个 daemon 的 GPU。
索引重建 不允许并发写。 Chroma 重建锁、代码图谱重建锁、跨层链路临时库发布。
源码文件 不同文件可并行。 发现他人改动先读最新内容,不回滚未知改动。
本仓 codev-platform 自身改动 不允许并发改 + 同时 daemon 持旧。 改完 commit + push + 各业务仓重启 daemon(Stop-Process port 18083)。
会话 / 记忆持久化(数据库) 读可并发,写走短事务。 读写分离接缝(只读副本可选,不预建);连接池上限可调;主键带组织 + 用户维度物理隔离。
会话消息顺序(多窗口) 多窗口可并发写同一会话。 数据库自增序号定序,不在应用层算序号(免并发竞态);消息按序号读回。
记忆维护任务(到期归档 / 压缩融合) 不允许并发跑同一主题。 数据库会话级单实例锁(抢不到即跳过),防并发压同主题写出重复摘要。
多租户记忆访问 跨组织 / 用户读可并发。 所有读写带组织 + 用户维度;个人记忆只能读本人(召回 ≠ 直接读);授权层接缝留待多人期。

开发工作流

规则真值源在本仓 rules/workflow.md,经 sync-rules 推送到各业务仓 .claude/rules/。改前门禁:AI 做 L2/L3/L4 时,先产出合并影响面,再决定文件范围、生成边界和验证命令。

0. 自报 trigger

会话首次 Bash / Edit / Write 前输出 [L1|L2|L3] 任务: ... → MCP 计划: ...。把"知道映射表"转成"动手前真查"。

1. 判级

L1 小改轻流程。L2 单层查规则+影响面。L3 跨层查三套 MCP。L4 高风险先说边界。

2. 查证

规则靠 platform-docs,代码结构靠 codegraph,数据契约靠 graph。dirty 命中读真实文件。

3. 定边界

合并影响面 → 文件归属、禁改项、生成项、验证命令。提效核心。

4. 修改

只改本次范围。生成物、历史迁移、索引产物、缓存默认不手改。

5. 验证

定向 lint / test / compile / 体检 ai-health。

合并影响面来源(MCP)用途
规则 / 红线 / skill 步骤 platform-docs (本仓 chroma daemon) 决定能不能改、必须怎么改、哪些命令禁止自动跑。
函数 / 类 / 调用方 / 影响面 代码图谱(业务仓索引) 决定改哪些代码文件、哪些调用方需要同步、哪里需要补测试。
SQL / 表 / 字段 / endpoint / Python writer-reader graph (本仓统一图谱 MCP) 决定跨层契约、DB 写入、Mapper、前端 API 类型和数据一致性风险。
真实工作树 dirty-index + 本地文件 发现索引滞后时兜底,防止多个会话同时改同一文件。
等级典型范围工具强度
L1文案、注释、局部样式、单文件小修。git status + 定向读 + 最小验证。
L2单模块或同层多模块联动,不改 API / DB / DTO / enum / 跨语言字段契约。模块 rules + codegraph 调用方/影响面;追问数据来源加 graph。
L3DTO、API、SQL、写库字段、migration、enum、跨层契约。platform-docs + codegraph + graph + 验证闭环。
L4生成文件、依赖、全局 runtime、AI 工具链、历史数据边界。先说明影响范围;禁改项拒绝或走正确生成流程。
