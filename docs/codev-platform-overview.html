这平台是什么 (一句话 × 4)

1. 真值源仓

Chroma 常驻服务、词法召回、统一图谱、project_id / paths / config 这些核心代码集中在这。业务仓 tools/_platform/ · tools/chroma/ 全是 thin shim re-export 自本仓。

2. pip 包

pip install -e D:\WorkSpace\codev-platform → 业务仓的 chroma .venv / system python 都能 import codev_platform.*。-e 软链,改源码即生效。

3. CLI 入口

codev-platform 20+ 子命令:接入(init / sync-rules / sync-skills / sync-hooks)、服务编排(serve-mcp / web / gateway)、运维(health / reindex / reindex-queue / index status / recall-stats / backup)、图谱与能力(graph / codegraph link / plugins list)。新业务仓接入与日常运维全靠它。

4. 用户配置中心

~/.codev-platform/config.json 单一文件:模型路径 / daemon 端口 / 数据基目录 / search 参数。换机器只改这,代码不动。

A. 平台骨架(这个平台怎么"长"的)

名词大白话解释在本平台里
真值源
(single source of truth, SSOT)		同一份东西只在一个地方维护,别处都引用它,不各自拷贝。codev-platform 仓就是所有业务仓的真值源:代码、规则、技能改这一处,处处生效。
pip 包 / editable 安装
(pip install -e)		Python 的"软链"装法:装的是指向源码目录的引用,改源码立即生效,不用重装。业务仓 pip install -e 本仓后就能 import codev_platform.*,平台改一行业务仓马上拿到。
shim(垫片)一个只有一行转发的小文件:from codev_platform.x import *,让旧的引用路径继续可用。业务仓 tools/_platform/ 下全是 shim,真代码都在平台仓。
CLI(命令行工具)在终端敲命令操作的程序,和"点鼠标的图形界面"相对。codev-platform 命令本体:接入、体检、重建索引、起服务都靠它。
daemon(常驻服务)一直在后台跑的进程,启动一次大家共用。检索模型(~3GB 显存)装进一个 daemon,所有项目所有会话共用,避免每个会话各加载一份把显存撑爆。
多租户(multi-tenant)一套服务同时服务多个"租户"(项目 / 组织),数据按租户标识隔离互不可见。所有服务按 project_id / org_id 路由,A 项目永远查不到 B 项目的数据。
contextvarPython 里"每个请求自带的小抽屉":并发处理多个请求时,各自的变量互不干扰。daemon 同时服务多项目请求,靠 contextvar 保证每个请求用自己的 project_id,不串库。
fail-soft / fail-fast软失败 = 某组件挂了就降级继续跑;快失败 = 发现配置不安全宁可拒绝启动。检索少一条 lane 照样出结果(fail-soft);多人共用却没开认证则直接拒绝启动(fail-fast),防身份串号。
幂等(idempotent)同一操作执行多次,效果和执行一次一样,重试安全。sync-hooks、codegraph link 等命令反复跑不会越跑越乱。

B. AI / 大模型

名词大白话解释在本平台里
LLM(大语言模型)GPT / Claude / DeepSeek 这类模型的统称。Agent 的"脑子";A1 / A2 图谱标注、记忆压缩也用它。
token模型计费和长度的单位,粗略 ≈ 一个汉字 / 半个英文单词。检索系统的核心价值之一就是省 token:只挑相关片段给模型,不整仓塞。
上下文窗口
(context window)		模型一次能"看见"的内容上限。预索引 + top-k 召回让有限的窗口装的全是相关内容。
prompt / 系统提示词
(system prompt)		给模型的指令文本;系统提示词是每轮对话开头固定注入的那部分。Agent 把召回到的记忆 / 规则注入系统提示词,模型"带着记忆"回答。
工具调用(tool use)模型不瞎编,而是声明"我要调 X 工具查一下",程序执行后把结果喂回给它。Agent 自带 9 个只读工具(查文档 / 查符号 / 查影响面…);Claude Code 调 MCP 也是这个机制。
Agent / agent loop让模型"计划 → 调工具 → 看结果 → 再计划"循环跑、直到给出答案的程序框架。agent/loop.py;还带防空转硬护栏:重复调用拦截、倒数步强制收尾。
planner(规划器)循环外层先给问题分类(找符号?查影响面?查文档?),据此分配工具预算和停止条件。确定性(规则)分类版已上线;LLM 版经 A/B 实验证明无增益,默认关。
provider / 协议族
(protocol family)		provider = 一家模型服务;协议族 = 它们 API 说话的格式。市面 95% 模型兼容 OpenAI 协议格式。平台铁律:按协议族写适配器(2 个文件),厂商只是 config 数据 —— 加一家模型零代码。
LLM-judge用一个模型给另一个模型的输出打分,实现自动评测。agent 端到端 eval 的打分手段之一。
prompt cache(提示词缓存)模型厂商对重复出现的前缀打折计费。agent 多步循环里前缀大量重复,实测缓存命中 ~80%,省约 74% 成本。

C. 检索与召回(平台的核心本事)

名词大白话解释在本平台里
向量嵌入(embedding)把一段文字变成一串数字(向量),意思相近的文字向量也相近 → "按意思搜"的基础。Qwen3-Embedding 模型把文档 / 代码嵌入向量,存进 Chroma 向量库。
语义检索 / 向量召回
(semantic search / vector recall)		用向量找"意思相关"的内容,哪怕用词完全不同也能命中。search_docs 的主路;代码语义 vector lane 补"按行为找代码"盲区。
BM25搜索引擎的经典关键词打分算法,擅长精确词命中(版本号、规则编号、罕见标识符)。词法召回 lane,专补向量检索"漏掉精确词"的短板。
倒排索引
(inverted index)		"词 → 出现在哪些文档"的反向索引表,BM25 的底层结构。chroma/bm25.py 维护,每个项目独立一份。
jieba 分词中文分词库。中文没空格,得先切成词才能建倒排索引。中英混合文档的词法召回靠它切词。
lane(召回路)一条独立的检索通道,各查各的、互不依赖。代码召回有 vector / codegraph / graph 三条 lane;文档召回有向量 + BM25 两条。
RRF(倒数排名融合)把多条 lane 各自的排名合成一个总排名:在每条 lane 里排得越靠前得分越高,相加排序。简单且稳健。weighted RRF = 按 query 类型给不同 lane 不同权重;实测比单 lane 明显更准。
reranker / cross-encoder(重排器)召回拿到前几十条后,用一个更重的模型对"问题 + 候选"逐对精细打分、重新排序。更准但更慢,只用在最后一步。Qwen3-Reranker 精排 search_docs 结果;代码召回的 reranker lane 实验中默认关。
top-k / chunktop-k = 只取前 k 条;chunk = 文档切成的小段,检索的最小单位。chunk 策略:目标 1000 / 上限 1500 字符,按标题 → 段落 → 硬切三级。
MRR / nDCG检索质量的两个评测指标:MRR 看"第一个正确答案排多前",nDCG 看"整个排序质量"。0~1,越大越好。代码召回用 35 条跨项目人工金标回归;vector lane 消融实测 MRR +0.43(本仓)/ +0.57(业务仓),bootstrap 置信区间全正(不挂单一绝对值 —— 早期 6 例的 0.917 是易集饱和假象)。
消融实验(ablation)去掉某个组件再跑评测,看指标掉多少,反推这个组件的真实贡献。"三路融合 vs 两路"就是消融:砍掉 vector lane,MRR 掉 0.43~0.57 → 证明 vector lane 真有用,不是凑数。
金标(golden set)人工标注的"标准答案"题库,改了检索逻辑就拿它回归测一遍,防变差。代码召回 35 条金标;agent 也有端到端评测集。
A/B 测试 + 置信区间
(A/B test · confidence interval)		两个方案各跑同一评测集,用统计方法(bootstrap 置信区间)判断差异是真提升还是随机波动。平台上线检索 / planner 改动前都先 A/B:增益不显著就默认关,不拍脑袋。

D. 代码图谱与影响分析

名词大白话解释在本平台里
codegraph(代码图谱)把代码解析成"符号(函数 / 类)+ 调用关系"的图,能回答"谁调用了它 / 它调用了谁"。9 个 MCP 工具(search / callers / callees / impact / context…)。
AST(抽象语法树)编译器视角的代码结构树,比文本正则匹配可靠得多。图谱解析的基础:从 AST 抽符号和调用边。
统一图谱(graph)
(unified graph)		跨语言跨层的图:前端页面 ↔ API 端点 ↔ SQL 表的链路全连起来。"改这张表会影响哪些页面"一查便知;8 个 MCP 工具。
节点 / 边
(node / edge)		图的基本元素:节点 = 实体(函数 / 表 / 页面),边 = 关系(调用 / 读写 / 依赖)。GraphNode / GraphEdge 中性类型,所有扫描插件的通用货币。
BFS(广度优先搜索)从一个节点一圈一圈往外扩的图遍历方法。影响面分析 = 反向 BFS:从被改的节点逆着依赖边往外找波及范围。
影响面(blast radius)改一个东西会波及哪些东西,直译"爆炸半径"。codegraph_impact / find_impact,改代码前必查。
血缘(lineage)数据 / 调用"从哪来、到哪去"的链路。统一图谱的跨层血缘:页面 → 端点 → 服务 → 表。
provenance(来源追溯)每条边记着"它是被什么方法发现的"(AST 解析 / 框架约定 / 正则启发),来源决定可信度。impact 查询可按 certain_only 只看高可信边。
置信度(confidence)0~1 的可靠程度打分。低置信边可被过滤;图谱审计会报告低置信边占比。
软节点 / 硬节点
(soft / hard node)		硬节点 = 从代码硬解析出的事实;软节点 = LLM 或规则"理解"出来的标签。A1 业务域、A2 架构分层(controller / service / repository…)都是软节点,带置信度、可重算。
跨仓图谱 / extra_repos一个项目的代码分散在多个 git 仓(典型:前端一个仓、后端一个仓);把关联仓声明进来,图谱就能跨仓把链路连起来。统一图谱按 extra_repos(project-id 引用,可移植)合并关联仓节点,前端仓的调用能连到后端仓的端点;RepoScope 给各仓节点打仓标签防同名文件碰撞(主仓标签为空,零改动)。
边质量 / 深度衰减
(edge quality · depth decay)		影响面 BFS 不把所有边一视同仁:按"关系强度 × 来源可信 × 置信度"给每条边打质量分,且越远的依赖权重越低。Phase 5:强依赖(调用 / 读写)权重 1.0,弱关系(imports 0.85 / mentions 0.6)降权;每跳乘 0.9 衰减 → find_impact_paths 把"最可能真受影响"的路径排前面。

E. 服务与通信

名词大白话解释在本平台里
MCP(Model Context Protocol)Anthropic 提出的标准协议,让 AI 编程工具(Claude Code 等)用统一方式调用外部工具和数据源。平台对 AI 暴露的 4 套检索服务(文档 / 代码图谱 / 统一图谱 / 团队记忆)全是 MCP 服务。
SSE(Server-Sent Events)HTTP 上"服务器 → 客户端"持续单向推送的技术。MCP 远程传输方式:业务仓 .mcp.json 连 http://…/sse?project_id= 服务地址。
stdio标准输入输出管道,进程间最朴素的通信方式。MCP 的本地传输(每会话 spawn 一个子进程)。平台已升级为 SSE 常驻服务支持多人共享,stdio 留作单机回退。
FastAPIPython 的现代 Web 框架,写 HTTP API 用。Agent 服务和 Web 管理后端都用它。
endpoint(端点)HTTP API 的一个具体接口地址,如 POST /chat。统一图谱里"端点"也是一类节点,连接前端调用与后端实现。
webhook反向通知:事件发生时,源头主动发 HTTP 请求告诉你,不用你轮询。Git 服务器 push 时调平台 webhook → 自动入队重建索引,索引随提交自动保鲜。
HMAC 验签用共享密钥对消息算签名,收方核对,确认请求真来自对方而非伪造。webhook 入口验签,防止伪造请求触发重建。
OpenAPI / 生成 API 层HTTP API 的机器可读说明书;前端按它自动生成调用代码和类型。web-ui 的接口层由后端 OpenAPI 生成(pnpm run api),前端不手写接口类型,杜绝前后端字段漂移。

F. 存储与并发

名词大白话解释在本平台里
SQLite单文件嵌入式数据库,零部署零运维,适合单机。单机模式下图谱 / 会话的默认后端,一个项目一个文件。
PostgreSQL(PG)服务器级关系数据库,多人多机共享场景的标配。多机模式:reindex 队列、统一图谱、会话、记忆、RBAC 全落 PG 共享。
双后端 + 工厂
(dual backend · factory pattern)		同一套接口、两套实现(SQLite 单机 / PG 共享),由"工厂"按配置决定造哪个。GraphStore / JobQueue / SessionStore 都是这个模式;契约测试保证两套行为一致。
WAL(Write-Ahead Log)SQLite 的日志模式,读和写互不阻塞。本地库默认开 WAL,daemon 读时后台还能写。
migration(迁移)/ alembic数据库表结构的版本管理:每次改表写成带编号的脚本,任何机器按顺序执行就升到最新。PG 库的 schema 演进全走 alembic 编号脚本,多机不漂移。
事务(transaction)一组数据库操作"要么全成、要么全不成"。会话 / 记忆写入走短事务,保证不写半截。
SKIP LOCKEDPG 的"抢任务"语法:多台机器同时取任务,已被别人锁住的行直接跳过,天然防重复消费。PgJobQueue 多机认领 reindex 任务的核心机制。
advisory lock(咨询锁)PG 提供的应用级锁:抢到才干活,抢不到就跳过。记忆维护任务用它保证同一主题同时只有一个实例在压缩。
单写者(single-writer)同一份数据同时只允许一个进程写,读随便 —— 防止并发写把索引写坏。所有索引重建必须经队列串行消费,绝不两个进程同时写一份索引。
队列(job queue)+ worker"活儿先排队,worker 一个一个干"。提交代码 → 任务入队 → worker 按序重建索引;多机时 PgJobQueue 共享一个队列。

G. 安全与权限

名词大白话解释在本平台里
认证 vs 授权
(authentication / authorization)		认证 = 你是谁;授权 = 你能干什么。先认证后授权。gateway 验 token 是认证;RBAC 查角色权限是授权。
Bearer tokenHTTP 请求头里携带的"令牌"字符串,服务端据此识别身份。多人服务器模式的身份凭证;SSE 客户端带不了 header 时走 ?token= query 参数兜底。
RBAC(基于角色的访问控制)权限不直接发给个人,而是发给"角色"(viewer / member / admin),人挂在角色上。org > team > project > personal 四层作用域 × 角色 × 动作的权限矩阵。
org(组织)与隔离红线
(organization · isolation red line)		多租户的最外层单位;用户可属多个 org,但 org 之间数据严格隔离。跨 org 不可见是平台红线;token 必须绑 org;有结构守护测试防止任何端点漏挂权限闸。
passthrough(透传模式)"不验身份直接放行"的开发模式。单机自用合法;检测到多人共用会 fail-fast 拒绝启动,必须切 token 模式,防个人记忆串号。
审计日志(audit log)"谁、什么时候、对什么、做了什么"的流水账。平台操作留痕,Web 管理台 /system/audit 可查。
脱敏(redact)日志落盘前抹掉敏感内容(密钥 / 路径 / 问题原文)。生产日志模式自动脱敏。
限流(rate limit)滑动窗口数请求次数,超频拒绝,保护后端资源。gateway 按身份计数限流,防止单用户打爆模型和存储。

H. 工程化

名词大白话解释在本平台里

平台的作用与优势

作用 —— 平台在做的 5 件事

1. 一份真值源,多项目复用

核心代码 / 规则 / 技能 / 配置集中本仓,业务仓只靠 shim + sync 消费,不各自拷贝、各自演化。改一处,全仓生效。

2. AI 协作的检索底座

四套 MCP(代码图谱 / 跨层链路 / 文档检索 / 团队记忆)预索引。AI 改代码前先查定义、调用链、影响面、规则,少凭记忆瞎改 —— 准确率的地基。

3. 常驻 Agent 服务

FastAPI 多模型可插拔(按协议族,加厂商≈零代码),自带平台工具集(图谱 / 影响面 / 文档检索 / 记忆)+ 防空转护栏。从"被动检索"升级为"主动问答 / 执行",可被 web-ui / CLI / 会话调用。

4. 分层记忆基建

组织 / 团队 / 项目 / 个人四作用域,跨会话不失忆;召回融合 + 冲突消解(红线最高)+ 生命周期(TTL / 压缩)。让 AI 记住偏好与约定,不必每次重教。

5. 多租户 + 跨平台运维

一套服务多项目按 project_id / org/user 物理隔离;运维编排升级为跨平台 CLI,Win / Mac / Linux 一份 config 通用。

检索召回融合(recall)— 多路并发查,融成一个排名

"找代码 / 找文档 / 找记忆"都不押宝单一手段,而是多条 lane(召回路)并发各查各的,再用 weighted RRF 融成一个总排名。每条 lane 擅长不同盲区,谁挂了就少谁(fail-soft),不会整体瘫;权重按 query 类型自动选。

vector(语义向量)"按意思找" —— 描述行为 / 意图,哪怕用词和代码完全不同Qwen3-Embedding 把代码 / 文档嵌入为向量,近邻搜索

graph(跨层)跨层链路 —— 页面 ↔ 端点 ↔ 表统一图谱节点检索

并发治理

多项目 + 多会话是常态。策略不是禁止多进程,而是按资源类型区分:读可以并发,写必须串行,重资源必须单例。这套语义靠 codev_platform/chroma/server.py 的 contextvar 路由 + GPU semaphore + reindex lock 落地。

资源 允许并发 当前保护
AI 会话 / proxy 允许多个(跨项目 + 同项目多会话)。 每个会话声明文件范围;不得同时改同一文件;修改前后看 git status。
MCP 查询 允许多个读请求(跨项目按 contextvar 隔离)。 dirty-index 决定索引可信度;命中 dirty 后读真实文件兜底。
GPU 模型 不允许多份重模型 worker。 platform-docs shared daemon + spawn lock + health 检查;所有项目共享同一个 daemon 的 GPU。
索引重建 不允许并发写(单写者)。 一律经 reindex 队列串行消费;Chroma / 代码图谱重建锁带 PID 存活检查,死锁持有者立即抢占。
多机任务认领 多台机器可同时当 worker。 PgJobQueue:PG SKIP LOCKED 行级认领 + claim_token;worker 崩溃后任务按 owner(主机名)恢复,不重复消费、不丢任务。
源码文件 不同文件可并行。 发现他人改动先读最新内容,不回滚未知改动。
本仓 codev-platform 自身改动 不允许并发改 + 同时 daemon 持旧。 改完 commit + push + 重启持旧代码的服务(serve-mcp start 重拉 / WSL systemd restart)。
会话 / 记忆持久化(数据库) 读可并发,写走短事务。 读写分离接缝(只读副本可选,不预建);连接池上限可调;主键带组织 + 用户维度物理隔离。
会话消息顺序(多窗口) 多窗口可并发写同一会话。 数据库自增序号定序,不在应用层算序号(免并发竞态);消息按序号读回。
记忆维护任务(到期归档 / 压缩融合) 不允许并发跑同一主题。 数据库会话级单实例锁(抢不到即跳过),防并发压同主题写出重复摘要。
多租户记忆访问 跨组织 / 用户读可并发。 所有读写带组织 + 用户维度;个人记忆只能读本人(召回 ≠ 直接读);授权层接缝留待多人期。

开发工作流

规则分两层:本仓工作规则在 .claude/rules/;跨项目通用真值源在 codev_platform/resources/rules/,经 sync-rules 推送到各业务仓 .claude/rules/。改前门禁:AI 做 L2/L3/L4 时,先产出合并影响面,再决定文件范围、生成边界和验证命令。

0. 自报 trigger

会话首次 Bash / Edit / Write 前输出 [L1|L2|L3] 任务: ... → MCP 计划: ...。把"知道映射表"转成"动手前真查"。

1. 判级

L1 小改轻流程。L2 单层查规则+影响面。L3 跨层查多套 MCP。L4 高风险先说边界。

2. 查证

规则靠 platform-docs,代码结构靠 codegraph,数据契约靠 graph。dirty 命中读真实文件。

3. 定边界

合并影响面 → 文件归属、禁改项、生成项、验证命令。提效核心。

4. 修改

只改本次范围。生成物、历史迁移、索引产物、缓存默认不手改。

5. 验证

定向 lint / test / compile / 体检 ai-health。

合并影响面来源(MCP)用途
规则 / 红线 / skill 步骤 platform-docs (本仓 chroma daemon) 决定能不能改、必须怎么改、哪些命令禁止自动跑。
函数 / 类 / 调用方 / 影响面 代码图谱(业务仓索引) 决定改哪些代码文件、哪些调用方需要同步、哪里需要补测试。
SQL / 表 / 字段 / endpoint / Python writer-reader graph (本仓统一图谱 MCP) 决定跨层契约、DB 写入、Mapper、前端 API 类型和数据一致性风险。
真实工作树 dirty-index + 本地文件 发现索引滞后时兜底,防止多个会话同时改同一文件。

L1文案、注释、局部样式、单文件小修。git status + 定向读 + 最小验证。
