## 2026-05-28 — codev-platform 大改造 session（平台翻正 + 可观测性 + 通用化 + 可移植化 + 跨平台 CLI）

本 session 把 codev-platform 从"名义真值源、运行时寄生业务仓"改造成"自包含、可审计、可移植、跨平台"的平台本体。六个主题，三仓（codev-platform / platform / widget）同步推进，全部落在各仓 `feat/xplatform-cli` 分支，**未 push、未合并**。

### 1. 平台所有权翻正

**做了什么**：把重资产（venv / 数据库 / data 目录 / launcher）从业务仓 `D:\WorkSpace\platform` 的所有权语义搬回 codev-platform，让本仓成为自包含平台，业务仓退化为纯消费 shim。落地范围：`pyproject.toml` 加 `[runtime]` 可选依赖组 + `requirements-runtime.txt`（锁 torch cu128）；本仓自建 `tools/chroma/platform-docs-mcp.cmd` / `tools/cross_link/cross-link-mcp.cmd` launcher 指向仓根 `.venv`；3 仓 `.mcp.json` launcher 重指 codev-platform 自有 `tools/`。

**为什么**：旧设计里 venv（4.66GB，绝对路径烤死不可搬）+ chroma/cross_link 数据物理住在 openclaw-stock 业务仓，平台运维寄生在业务里，推翻了 `CLAUDE.md §八`「venv 不在本仓、本仓 0 deps」的旧约束。用户 2026-05-28 拍板「全量自立」。

**关键 commit**（codev-platform）：`56d55e7` build runtime 可选依赖 + 锁文件 / `25b4e70` 自有 MCP launcher / `620aa3f` launcher 重指本仓 tools / `b87acc7` docs 翻正（CLAUDE.md 架构 + 迁移计划）。计划文件：`docs/plans/roadmap-2026-05-28/platform-ownership-inversion-2026-05-28.md`。

**状态**：源码 / 配置 / launcher 已就位（plan P1/P3/P5 完成）。venv 重建（P2）、数据搬迁（P4）、业务仓旧资产删除（P6 destructive）需用户手动执行，尚未真机走完。

### 2. MCP 可观测性

**做了什么**：cross-link MCP 加 `cross_link_usage.jsonl` 调用埋点；ai-health 聚合三套 MCP（platform-docs / codegraph / cross-link）使用率，给出 `mcp usage 7d` 视角。

**为什么**：此前无法判断 L2/L3 任务是否真按 `workflow.md §3.2` 用了 MCP，adoption 低到无法度量。埋点 + 聚合让"检索纪律执行情况"从靠自律变成可审计。

**关键 commit**：`8522102` observability cross-link 埋点 + ai-health 聚合。

**状态**：埋点 + 聚合已落地，随用量积累数据。

### 3. ai-health 通用化（零项目硬编码）

**做了什么**：ai-health 彻底配置驱动 —— reindex 范围 / 路径全走 meta.json 的 `health.*` + `config.json`，代码零项目耦合；加 `-Project` 参数可审计任意已登记项目；修了 chroma collection 检查未按 `project_id` 隔离的 bug（之前 codev / openclaw 显示同一份数据）；清理迁移后的误报 WARN。

**为什么**：原 ai-health 把 openclaw 业务路径写死在脚本里，新项目接入要改代码。配置驱动后新项目零改代码即可体检。

**关键 commit**：`e168c8d` 彻底配置驱动代码零耦合 / `6d575fb` 加 -Project 参数 / `e305636` chroma collection 按 project_id 隔离 / `ea4f26b` 清迁移误报 WARN / `a16bbf2` 共享基础设施路径跟随翻正。

**状态**：两仓体检归零误报，通用化完成。

### 4. 可移植化（去机器路径硬编码）

**做了什么**：所有机器相关路径（venv / python / 模型 / 数据目录）收敛到 `config.json`；wrapper 的 canonical 路径改 `$PSScriptRoot` 相对推导；`install-git-hooks` 改用 `git rev-parse` 解析当前仓，任意项目可用；cross_link subprocess 兼容 `.cmd`/`.ps1` launcher（`_winexec`，Py3.12+）。reindex 触发范围也改为配置驱动，新项目零改代码。

**为什么**：硬编码 `D:\WorkSpace\...` 在任何其他机器 / 队友环境全废。配置化 + 相对解析是后续跨平台的前置条件。

**关键 commit**（codev-platform）：`a754212` 模型路径 + memory cwd 配置化 / `68d139e` install-git-hooks git rev-parse / `85d4678`+`7ea0b50` update-local-ai 从 config 解析 python/venv / `b6fa223` 去 legacy fallback 杜绝跨项目串数据 / `e0483e0` reindex 触发范围配置驱动 / `d04eae4` widget reindex codegraph 模式。platform 仓：`514f136` wrapper canonical 相对推导 / `ef38c8e` cross-link subprocess 兼容 .cmd/.ps1。

**状态**：路径硬编码清零，可移植化完成。

### 5. 跨平台 CLI 重构

**做了什么**：把 Windows-only 的运维 `.ps1` 编排逻辑收进 `codev_platform.ops` Python 包 + CLI 子命令（`health` / `reindex` / `post-commit` / `dirty-check` / `install-hooks` / `wait`）；新增 `ops/{_common,hooks,reindex,health}.py`，`_common.run()` 吸收 `_winexec` 做跨平台 subprocess 路由（Windows 走 cmd/powershell，Linux/Mac 直跑）；git hook 改 `exec codev-platform post-commit`，去掉 `WindowsPowerShell\v1.0\powershell.exe` 硬编码；platform / widget 仓的运维 wrapper 退化为转调跨平台 CLI 的薄 shim。

**为什么**：重活（daemon / 索引器 / cross_link / 健康探针）早已是 Python，`.ps1` 只是 Windows 编排壳，移植到 Linux 服务器 / 队友 Mac 会全废。一套 Python CLI 全平台通用。

**关键 commit**：codev-platform `bb7a809` 跨平台 CLI 子命令替 .ps1。platform 仓 `7a3be6b` / `318f45a` / `ebcfc3b` wrapper 转调 canonical CLI。widget `b0c461a` / `7160225` 同。计划文件：`docs/plans/roadmap-2026-05-28/xplatform-cli-2026-05-28.md`。

**状态**：CLI 子命令在 Windows 落地。Linux/Mac 真机冒烟（`pip install -e .[runtime]` + `codev-platform health`）尚未做。

### 7. 运维编排跨平台化（.ps1 → Python CLI）

**做了什么**：把原本散在 `scripts/*.ps1` 的运维编排全收进 `codev_platform.ops` Python 包 + 6 个 CLI 子命令 —— `health`（体检，端口/会话/索引新鲜度全探）、`reindex`（chroma/codegraph/cross-link 三阶段，可选子集）、`post-commit`（git hook 入口，按改动 scope 分类后台触发，永不 fail commit）、`dirty-check`（工作树 dirty 文件是否命中索引范围，0/1/2 退出码供 AI 判 MCP 可信度）、`install-hooks`（写跨平台 sh stub）、`wait-for-reindex`（轮询 reindex.log 直到目标 commit 完成）。

**为什么**：重活（daemon / 索引器 / cross_link / 健康探针）早已是 Python，`.ps1` 只是 Windows 编排壳，移植到 Linux/Mac 全废。一套 Python CLI 全平台通用，`.ps1` 退化为薄 shim 转调 CLI。

**关键 commit**：`bb7a809` 跨平台 CLI 子命令替 .ps1。

### 8. "验证触发"揪出并修的迁移遗留

跨平台化收尾时逐项验证，揪出一批平台翻正后的硬编码 / 路径遗留并修掉：

- `post-commit` / `dirty-check` wrapper 改转调 canonical CLI（去重复实现）。
- `update-local-ai` 的 chroma venv + cross_link python 从 `config.json` 解析（`7ea0b50` / `85d4678`），去硬编码。
- `_winexec` 兼容 `.cmd` / `.ps1` launcher（Py3.12+），cross_link subprocess 跨平台路由。
- `install-git-hooks` 改 `git rev-parse` 解析当前仓（`68d139e`），任意项目可用。
- cross_link 去 legacy fallback（`b6fa223`），杜绝跨项目数据串用。
- 模型路径残留：`indexer.py` / `config.py` 去掉代码层 `D:\models` 硬编码，全配置驱动（`4ea3589`）。

**教训**：迁移类改造"看起来改完了"不等于"改干净了"，逐子命令实跑验证才暴露 wrapper 重复实现、config 没接上、`.ps1`/`.cmd` 启动器不兼容等暗坑。
