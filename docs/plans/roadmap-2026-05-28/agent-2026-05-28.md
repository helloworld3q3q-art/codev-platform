# Agent 开发 Plan(2026-05-28)

> **前提**:平台已提供 agent 的"感官"—— 3 个 MCP(platform-docs 语义检索 / codegraph 代码图谱 / cross-link 跨层链路)+ 跨平台 CLI 控制平面。缺的是"大脑回路"(LLM + 循环 + 目标)。
>
> **核心原则**:**agent 核心(循环+工具)与前端(壳)解耦**。核心一份,CLI/桌面/Claude-Code 都是壳。先写核心,壳分阶段套。
>
> **本体不是商业产品**(见 commercialization 讨论):agent 的价值是"用平台做出能跑/能讲故事的东西",优先验证循环可用,而非一步到位。

---

## 一、技术方案

### 1.1 分层架构(解耦)

```
┌── 前端壳(可换)──────────────────────────────┐
│  Claude Code skill/subagent  │  CLI: codev-platform agent  │  桌面 widget chat │
└──────────────┬───────────────────────────────┘
               │ 同一份核心
┌── agent 核心 codev_platform/agent/ ──────────┐
│  loop.py    决策循环 (plan→tool→observe→act→stop)            │
│  brain.py   LLM 适配 (Anthropic SDK / 本地 LLM / Claude Code) │
│  tools.py   工具封装 (调 MCP 或直接调 codev_platform Python API)│
│  memory.py  上下文/历史 (复用检索压上下文)                     │
└──────────────┬───────────────────────────────┘
               │
        平台 MCP / Python API
   chroma 检索 · codegraph · cross-link · dirty-check(判索引可信)
```

### 1.2 大脑(LLM)选型 —— 分阶段

| 阶段 | 大脑 | 说明 |
|---|---|---|
| PoC | **Claude Code 自身** | agent=skill/subagent,复用 Claude + MCP,零接模型零循环 |
| 独立 | **Anthropic SDK(Claude API)** | 标准 tool_use 循环,agentic 能力最强,花 token |
| 私有(可选)| 本地 chat LLM(Ollama/vLLM:Qwen-Instruct/DeepSeek)| 0 API 费 + 私有,8GB GPU 跑量化 7B,agentic 弱 |
| 注 | embedding/reranker(现有)**不是大脑**,只做检索 | — |

### 1.3 工具接入

- agent 调平台能力两种方式:① **MCP client**(与 Claude Code 一致,复用 daemon)② **直接调 codev_platform Python API**(in-process,快,标准 agent 推荐)。
- **关键**:agent 调用前先 `dirty-check` 判索引可信(dirty 命中则回读真实文件),否则会基于过期索引决策(workflow.md §2.2 教训)。
- 工具选型逻辑直接喂 workflow.md §3.2 映射表(找代码→codegraph / 找规则→search_docs / 找链路→cross-link)。

## 二、产品规划(分阶段,窄→宽)

| 阶段 | 形态 | 能力 | 壳 | 工期 |
|---|---|---|---|---|
| **P0 验证** | 只读问答 agent(候选 A)| 问"X 怎么实现/改 Y 炸哪/规则在哪"→ 调 codegraph+cross-link+search_docs 给带证据答案 | Claude Code skill | 几天 |
| **P1 独立** | CLI agent | 同 P0,但脱离 Claude Code 独立跑(headless/服务器/cron 可用)| `codev-platform agent "<task>"` | 1-2 周 |
| **P2 写** | 维护 agent(候选 B)| issue→查→改→跑测试→出 PR 草案 | CLI + 人工审 | 后续 |
| **P3 宽** | 桌面/业务(C)| widget chat 面板 OR openclaw 盘后自动复盘 | 桌面 / 服务 | 价值验证后 |

**先 P0 证明"循环+检索能干活",再 P1 独立化,P2 才碰写,P3 才上桌面/业务。** 不跳级。

## 三、难点(诚实)

| # | 难点 | 为什么难 / 对策 |
|---|---|---|
| 1 | **循环可靠性** | LLM tool-use 循环会跑偏/死循环/幻觉 → 必须 step 上限 + 停止条件 + 错误恢复 + 每步可观测 |
| 2 | **工具选型** | agent 得选对 MCP(codegraph vs cross-link vs search_docs)→ 喂 §3.2 映射 + few-shot;选错=答错 |
| 3 | **上下文管理** | 长任务爆 context → 用检索只拉相关 chunk(平台的强项正好救这个)+ 阶段性 summary |
| 4 | **验证/eval** | 怎么知道 agent 答得对/改得对?→ 要 eval 集(接上你刚建的 pytest/CI;agent eval 比单测难,需 golden 问答 + 人工抽检)|
| 5 | **写安全(P2)** | 自动改代码风险高 → dry-run + 人在环审批 + 测试必过 gate + 可回退;别让 agent 直接 push |
| 6 | **索引新鲜度** | agent 基于索引决策,dirty/未提交看不到 → 每次决策前 dirty-check,命中则回读真文件 |
| 7 | **本地 LLM 弱** | 若走私有本地 LLM,agentic 能力远逊 Claude → PoC/P1 先用 Claude API 验证,私有化是后期工程 |
| 8 | **成本/延迟** | Claude API 按 token 计费 → 检索压小上下文(已有)+ 缓存 + 限 step 控成本 |

## 四、第一步(P0 最小闭环)

1. 做一个 Claude Code skill `ask-codebase`(或直接对话):接收问题 → 按 §3.2 调 codegraph_context + cross-link + search_docs → 综合给带文件/行号证据的答案 + 影响面。
2. **不写循环代码**(Claude Code 的循环现成),**不接模型**(用 Claude Code 的 Claude)。
3. 验证点:答案准不准、是否真用了 cross-link 差异化、证据是否可追溯。
4. P0 跑顺 → 再抽出核心做 P1 的 `codev_platform/agent/` + CLI。
