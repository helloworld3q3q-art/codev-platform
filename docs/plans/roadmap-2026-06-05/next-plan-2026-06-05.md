### Track A1 — 业务域映射(只读 MVP,本轮唯一综合理解步)✅ 已完成(实测 95% ≫ 70% 门槛)

在统一图谱 + Agent 底座之上, LLM 给 endpoint 链路归业务域。**不碰 plugins**(护城河)。

**架构定位(架构专家)**: analyzers 是 ingest 的 **second post-pass**(在 `_calls_pass` 之后),
独立 `graph/analyzers/base.py`(协议族+registry, 与 call_resolvers 平级),**不混进 plugins**。

**三道护栏(缺一即 PPT)**:
| # | 护栏 | 怎么做 |
|---|---|---|
| ① **grounding** | LLM 当 labeler 不当 extractor | closed-world 喂 `generate_impact_report` 输出(endpoint→表清单), "只能从清单 token 归纳, 不许引入清单外实体";**越界节点代码 reject 重试**(硬约束>prompt) |
| ② **软/硬隔离** | 保护"查依赖"护城河 | 独立 `NodeKind.BUSINESS_DOMAIN` + `EdgeKind.BELONGS_TO_DOMAIN`;**confidence 强制 <1.0**;软节点 meta 带 `derived_by=llm/model/prompt_version/source_node_ids`;**impact BFS 默认过滤软边**(查依赖不串, 查理解才放开);落库前过**确定性 referential-integrity 校验**(软边端点必须指向真实硬节点, 悬空即丢) |
| ③ **纠错回路** | PPT vs 真功能分水岭(产品专家) | LLM 必错 → ownership 支持**一键纠正 + 持久化复用**(改过的 domain 不被下次 LLM 覆盖) |

**成本控制(AI+实施专家)**:
- **cluster-batch**: 先确定性连通分量/Louvain, 一个 LLM call 标一个域(O(域数) 不是 O(节点数))。
- **node-subgraph fingerprint 缓存**: key = `hash(子图序列化 + model + prompt_version)`——LLM 非确定性,
  换模型/改 prompt 必失效(frontend_deps 无此问题, LLM 有)。失效**按 flow/链路粒度**(domain 跨节点, 非单文件)。
- **token 预算 + 子图采样**: 大仓(openclaw 4427 chunks)禁全图喂, 先采样护栏。
- **analyzer 按难度配 model**: domain 命名用本地小模型(Qwen)够, 走 brain 多 provider 路由。

**understand() 工具(架构 O1)**: 只读组合视图(BFS 硬边 join 软节点), **不在工具内触发 LLM**——
LLM 只在 ingest 跑一次落库, 查询零延迟可复现。

**验收(实施专家, 可证伪)**: 选 1 仓(openclaw-stock)、10 个 endpoint, **人工核对 domain 准确率 ≥70%**。
低于 70% = 方向证伪, 及时止损。
> ✅ **实测 95%**(真 deepseek 验收, 详见 memory `a1-business-domain-analyzer`): 三护栏 + cluster-batch +
> fingerprint 缓存 + ownership 一键纠错全落地; 聚类用 file 主信号(共享表会退化巨型 cluster, 58%→95%)。
> A1 落地后又补 **统一图谱 MCP**(第5端点把 A1+impact 接开发端 agent)+ **cross-link 退役**(graph 承接,
> -3300 行); 详见 daily-summary §十四~十六 + memory `cross-link-retired-graph-takeover`。

- ❌ **A2/A3/A4 本轮不做**(架构分层/tour/web-ui/persona)——推下轮专轮, 先证 A1 方向(实施+产品专家)。

  - **拆开看 UA 的 `tree-sitter + LLM agent` 组合**: 确定性层**不做**(plugins+codegraph 已等价**且更深**——
    UA 的 tree-sitter 只到 AST 不建调用/跨层边, 我们有 callers/impact/cross-link/DI resolver);

    codev 是 `确定性图谱(impact report)→LLM`(grounding-first, 越界 reject, 信息密度高于裸 AST)。
  - **唯一例外(非本轮)**: 将来支持 plugins 未覆盖的语言(Go/Rust/C++)时, tree-sitter 的"广度开箱"
    才有真增量——届时是"快速拿符号级广度"的**补充**, 不是替换 plugins。本轮无此类仓, 有需求再说。

- ❌ **persona 三档画像系统**(过度设计;若做降为 `concise/verbose` 两档开关, 第一档喂 agent)。
- ❌ **language-concepts 高亮**(纯教学花架子, 与 codegraph 重叠)。
- ❌ **LLM 审 LLM 的 graph-reviewer**(用确定性 referential-integrity 校验替代, ROI 高)。
- ❌ **开发端 memory(Track M): org/team 写 + redline IDE 端写 + 本地↔平台双向同步**(本轮不做, 治理复杂留后;
  只做 personal/project 读 + personal 默认写, org/team 只读)。
- ❌ **M6 Connector / M7 多模态**(缓)。
- ❌ **盘点"未做"不 Bash 直读就动手**(本会话 6 次文档滞后误判教训)。

## 七、设计哲学

技术血缘是**骨架**(plugins 产, 确定性, 不动), 综合理解是**血肉**(LLM analyzers 产, 软节点, 隔离),
在统一图谱上长在一起但**物理可分辨**(NodeKind + confidence + meta)。UA 是 "graphs that teach"(纯
LLM, human-first);codev 是 **"graphs that explain on a deterministic skeleton"** —— 确定性骨架
grounding LLM(比 UA 更抗幻觉), 产物服务 agent(AI-first), 多租户隔离(UA 没有)。

胜负手不在 UX, 在**业务域映射的准确(≥70% 可证伪)+ 可纠错(ownership 回路)+ 可被 agent/跨项目复用**。
