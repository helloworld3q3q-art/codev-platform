## 三、四条轨道(优先级 + 依赖)

### Track A — 综合理解层(spearhead, 最高优先)

在统一图谱 store(已有节点/边)+ Agent 平台(loop + 多 provider)之上跑 LLM 分析产高层理解。
**铁律: 不碰 plugins**(它喂技术血缘数据, 综合层站在其上;plugins 是护城河不动)。

| 步 | 任务 | 落点 | 验证 |
|---|---|---|---|
| **A1** | **业务域映射**: LLM agent 读图谱(endpoint/表/前端)→ 产 domain/flow/step(代码↔业务流程), 复用 cross-link 链路 | 新 `agent/analyzers/domain.py` + schema 加 domain 节点/边 + ownership 登记 | 给一个 endpoint 返回它属哪个业务域/流程 |
| **A2** | **架构分层**: 自动识别 API/Service/Data/UI/Util 层(`impact.py:layer_of` 已有雏形 → LLM 辅助精化) | `analyzers/architecture.py` | 节点带 arch_layer 标注, 跨层视图 |
| **A3** | **guided tour**: 依赖序学习路径(从入口/高 degree 节点 BFS + LLM 产可读 walkthrough) | `analyzers/tour.py` | 新人按 tour 顺序学某模块 |
| **A4** | **综合理解接口**: agent 工具 `understand(node)` → 业务域+架构+依赖+tour 综合;web-ui 可视化(persona 调详细度) | `agent/tools/understand.py` + web-ui | 一个节点出"它是什么/属什么业务/谁依赖/怎么学" |

> **架构对齐**: analyzers 走**协议族 + registry 铁律**(同 call_resolvers/plugins): 加一个分析维度 =
> 加一个 analyzer + 注册一行, 核心零改。LLM 调用走 brain(多 provider)。结果**缓存进 store**
> (避免每次 LLM, 文件未变复用 —— 同 frontend_deps fingerprint 缓存教训)。

  agent-sessions), 每次差点重复造轮子。**改任何"未做"项前先核实代码真实状态。**

## 七、与综合理解层的设计哲学

UA 的口号是 "graphs that teach > graphs that impress"。codev 的技术血缘是"graphs that query"
(给 AI/工程师查)。本迭代加的是 "graphs that **explain**" —— 在精确技术血缘之上, 用 LLM 把
"这块代码是什么业务、属哪一层、谁依赖它、新人怎么学"讲清楚。**技术血缘是骨架(plugins 产, 不动),
综合理解是血肉(LLM analyzers 产, 新增)**, 二者在统一图谱上长在一起。
