# 开源发布就绪计划

## 当前状态

开源发布材料已提交并受保护地推送；真实业务项目标识已从本地公开快照移除，独立公开快照分支已以单一根提交固化并完成全量公开边界审计，尚未推送；随后仍需完成第三方材料审计与 GitHub 设置确认

## 目标

在已将开源发布材料受保护地更新至 `origin/dev` 的前提下，使 `codev-platform` 的仓库材料达到可安全公开评估的状态；公开版本不得透露已接入的真实业务项目或其可识别线索。

## 范围

- 审计并补齐开源仓库的基础材料：许可证、README、贡献与安全披露说明、发布元数据和自动化门禁。
- 对受 Git 跟踪内容执行安全检查，识别公开前必须处理的敏感信息、内部专有配置或运行数据引用。
- 审计多项目机制在代码、配置、文档、CI、示例与 Git 历史中的实现痕迹；保留通用多租户能力，移除或泛化真实业务项目名称、标识、路径、仓库地址和项目数量线索。
- 为项目所有者指定的业务标识创建独立的本地 `open-source` 孤儿分支：移除其名称、链接、文档、文件路径和字面量，并以新的根提交替代全部既有 Git 历史。
- 审计公开快照中的大模型 provider API key、token、连接串和环境文件；任何真实凭据均移除或改为环境变量占位符，且不写入计划、提交信息或审计输出。
- 整理公开前仍需由项目所有者确认的授权、发布和运维决策项。
- 统一公开分支可达 Git 历史中的 author 与 committer 身份，消除不一致的历史署名。

## 非范围

- 不创建或公开 GitHub 仓库；未经项目所有者再次明确授权，不再推送远端。
- 不修改 `.venv/`、`data/`、`.codegraph/`、构建产物、用户级配置或迁移期 `.claude/**`。
- 不更改运行态、依赖版本、认证配置或生成的前端服务代码。
- 不改写远端、不会 force-push；仅在本地完成可恢复的历史重写。
- 本轮用户已明确授权：仅提交当前开源发布材料，并将当前 `dev` 更新到 `origin/dev`；因历史已改写，使用受保护的 force-with-lease，不推送 `origin`、其他分支或标签。
- 不在计划、审计报告、提交信息或公开示例中列出任何真实业务项目名称、项目 ID、项目数量、内部路径、仓库地址或运行数据。
- 仅创建本地 `open-source` 分支；未经项目所有者再次明确授权，不推送该分支，且不修改 `dev`、`origin`、其他分支或标签。

## 适用规则与约束

- `.codex/rules/workflow.md`：L4 发布前治理；计划和 roadmap 登记完成前不修改其他文件。
- `.codex/rules/file-discipline.md`：任务真值位于本目录，文档不新增 `docs/` 顶层散文件。
- `.codex/rules/security.md`：不将 token、API key、密码、用户数据或生产配置写入仓库或报告。
- `.codex/rules/verification-checklist.md`：按变更面运行最小、可复现的验证，并记录结果。
- `.codex/rules/commit-pr-conventions.md`：历史署名和提交信息不得保留不合规的归属标记。

## 实施步骤

1. 记录干净工作树和当前公开材料基线，审计受跟踪文件、Git 忽略规则、CI 与打包配置。
2. 确定许可证与开源发布边界；仅在可从仓库和既有授权中确定时落盘，否则保留为明确的用户决策项。
3. 补齐或重构公开 README、贡献指南、安全披露与发布检查清单，使其不依赖内部环境或私有资料。
4. 增加可自动验证的敏感信息与公开材料门禁，避免仅靠人工检查。
5. 运行文档、打包和目标测试验证；复核 Git diff，更新本计划与 roadmap 登记中的证据。
6. 交付开源发布检查清单和仍需项目所有者确认的事项。
7. 在项目所有者明确指定身份后，先备份 refs 和未提交改动，在隔离副本演练，再重写本地公开分支可达历史的 author 与 committer 身份；恢复未提交改动并验证所有可达提交的目标字段。
8. 以不回显真实标识的方式审计 Git 跟踪内容与将公开的历史，区分通用平台机制、可泛化示例和必须移除的真实业务痕迹。
9. 以稳定的匿名占位符和最小示例替换可识别业务项目信息；补充自动门禁，防止同类真实标识重新进入公开分支。
10. 在临时准备分支完成脱敏后创建 `open-source` 孤儿分支，使该分支仅有新的根提交；删除临时准备分支，保留 `dev` 原样作为私有开发历史。
11. 对 `open-source` 执行关键词、链接、路径与提交历史复核；审计命令中的私有关键词不写入公开分支、不写入提交信息或报告。
12. 对 `open-source` 的 Git 跟踪树和唯一根提交执行不回显的大模型凭据与通用密钥扫描；修复真实命中后重新验证。
13. 对 `open-source` 的完整提交快照执行第二轮公开边界审计：逐类检查 URL、域名、IP、仓库地址、用户目录、内部环境标识、凭据形态与业务专有名词；将不应公开的内容删除或替换为稳定的通用占位符。
14. 对修订后的公开快照重跑无回显扫描、链接分类检查、差异检查和受影响测试；确认根提交、分支上游和工作树状态符合发布边界。

## 验证方式

- Git 跟踪范围敏感信息扫描与忽略规则检查。
- README 链接、许可证文件、贡献与安全政策路径检查。
- 现有 pre-commit/CI 配置的定向校验。
- `python -m pytest tests/test_resources_packaging.py`（仅当发布元数据或包资源受到影响时）。
- `git diff --check` 与 `git status --short`。
- `git fsck --no-reflogs --full`、可达提交计数与 author/committer 身份统计；确认备份 ref、stash 和未提交改动可恢复。
- 仅输出命中类别、文件计数和已处理状态的脱敏审计；不回显真实业务项目标识，并在当前公开分支和待公开历史中复核无命中。
- `git log open-source` 仅包含新的根提交；对该分支的树、文件名、提交信息和所有可达 blob 执行不回显关键词的本地检查。
- 大模型 provider key、token、连接串、`.env` 与常见凭据模式扫描；仅记录命中类别和处理结果，不记录密钥或可用于重建密钥的片段。
